# Customer Journey Map (CJM) и сценарии AI-buddy

Целевой MVP команды состоит из трёх сценариев. Третий заменяет прежний поиск
владельца сервиса: по запросу стажёра бот создаёт PDF-черновик презентации на
основе выполненных задач из синтетического Jira mock. Автоматические напоминания
по расписанию и реальная Jira-интеграция в этот сценарий не входят.

> **Статус реализации:** решение о новом третьем сценарии зафиксировано
> 13.11.2026. В текущем коде пока остаётся старый сценарий поиска владельца и
> mock-сообщения; он будет удалён при реализации нового потока. Не считать
> сценарий презентации уже работающей функцией.

## Сценарий 1: «Быстрый старт» (интеграция + мок)

- **Этап CJM:** первая неделя.
- **Боль:** стажёру нужны доступы, но непонятно, куда обращаться и как оформить запрос.
- **Действие бота:** помогает оформить демонстрационную заявку на доступ через mock.
- **Интеграция:** защищённый agent flow Go → AI; результат заявки сохраняется в Postgres.
- **Результат:** стажёр видит номер и статус demo-заявки. Реальные доступы не выдаются.

## Сценарий 2: «Переводчик с Авито» (RAG)

- **Этап CJM:** первые недели.
- **Боль:** внутренние термины и процессы неочевидны, а отвлекать наставника по каждому вопросу неудобно.
- **Действие бота:** ищет ответ в разрешённых материалах и отвечает с источником.
- **Интеграция:** embeddings и retrieval в pgvector, генерация через Ollama.
- **Результат:** стажёр получает ответ со ссылкой на найденный источник либо честное сообщение, что подтверждённых данных нет.

## Сценарий 3: «Мои результаты» — черновик презентации по задачам

- **Этап CJM:** подготовка к промежуточному итогу адаптации.
- **Боль:** стажёру нужно собрать результаты работы, но описания задач разбросаны и трудно превратить их в краткий рассказ.
- **Действие бота:** по явному запросу собирает завершённые задачи демо-стажёра из синтетического Jira mock, структурирует факты и формирует PDF-черновик презентации.
- **Источник данных:** только [синтетический Jira fixture](../backend/testdata/jira_issues.json) с ключами, назначенными demo-пользователями, статусами, названиями и описаниями. В презентацию попадают только завершённые задачи текущего demo-пользователя.
- **Поток формирования:** Go выбирает завершённые задачи по доверенному demo-пользователю; AI получает только эту отфильтрованную выборку и возвращает структурированный JSON для слайдов с ключами исходных задач; Go проверяет, что ссылки на ключи принадлежат выборке, и сам рендерит PDF. AI не возвращает готовый PDF и не выбирает произвольные Jira-данные.
- **Результат:** пользователь получает PDF, визуально оформленный в стиле Avito и явно помеченный как демо-черновик. В документе можно проверить, из каких задач взяты факты.
- **Границы:** генерация запускается пользователем по запросу; расписания и фоновых уведомлений нет. Реальная Jira, настоящие данные сотрудников, автоматическая отправка и публикация презентации не используются.

### Структура PDF

1. Титульный слайд: демо-имя стажёра и период, только если они заданы fixture; иначе не выводить неподтверждённые сведения.
2. Краткие итоги: перечислить фактически выполненные направления, подтверждённые включёнными задачами.
3. Выполненные задачи: ключи, названия и описания задач; при необходимости кратко сократить описание без потери фактов.
4. Чему научился: только осторожные выводы, непосредственно подтверждаемые описаниями задач; если подтверждений недостаточно, показать это явно.
5. Следующие шаги: нейтральные предложения без дат и обещаний; явно пометить как предложения, а не факты или согласованный план.

### Критерии приёмки сценария 3

- Запрос пользователя явно запускает подготовку черновика; при обычном общении файл не создаётся.
- В выборку попадают только завершённые задачи назначенного demo-пользователя.
- Для fixture `backend/testdata/jira_issues.json` выборка demo-intern-001 должна включать DEMO-101, DEMO-102 и DEMO-103; DEMO-104 исключается по статусу, DEMO-105 — по assignee.
- PDF содержит ключ и название каждой включённой Jira-задачи, её описание или аккуратное сокращение описания, а также отметку о синтетических данных.
- Сгенерированные выводы опираются на описания задач; неизвестные сроки, метрики, достижения и технологии не придумываются.
- Если завершённых задач нет или данных недостаточно, бот сообщает об этом и не создаёт презентацию с вымышленными фактами.
- PDF доступен пользователю как скачиваемый файл; в интерфейсе показаны понятные состояния ожидания и ошибки.
- Каждый AI-тезис на слайдах 2 и 4 связан минимум с одним допустимым Jira-ключом; неизвестный ключ или неподтверждённое утверждение приводит к безопасной ошибке, не к публикации файла.
- Действие остаётся локальным демо: файл не отправляется в Jira, почту, Mattermost или другим людям.

## Не входит в текущий MVP

- Поиск реальных владельцев сервисов и отправка им сообщений. Прежняя демо-реализация будет удалена в рамках замены сценария.
- Реальное подключение к Jira, корпоративная IAM и персональные данные.
- Автоматическая отправка напоминаний, cron/scheduler и фоновые push-уведомления.
- Автоматическая публикация или рассылка сгенерированной презентации.
