# QA checklist: PDF-презентация

Чек-лист PM/QA для сквозной приёмки US3. Источник ожидаемого поведения —
[`../specs/presentation.spec.md`](../specs/presentation.spec.md).

## Перед тестированием

- [ ] Все три feature PR смержены в `main`, CI зелёный, есть ревью не от автора.
- [ ] Backend, AI и Frontend используют один согласованный контракт из спецификации.
- [ ] Backend проверил, что `demo_chat` cookie выставляется с `Path=/api`.
- [ ] В браузере созданы две независимые demo-сессии A и B.
- [ ] В Ollama доступны требуемые модели; модельный smoke test завершился
  без timeout/OOM.
- [ ] Все контейнеры запущены через `docker compose up -d --build`.

## Контракт ошибок

- Пустая выборка: `200`, `reply`, без `attachment`.
- AI timeout: `504`, `{ "code": "ai_timeout", "error": "..." }`.
- Невалидный ответ AI или неподтверждённый ключ: `502`,
  `{ "code": "ai_invalid_response", "error": "..." }`.
- Чужой, неизвестный или истёкший artifact: `404` без утечки сведений о чужой
  сессии.
- Повтор ключа запроса с иным текстом: `409`,
  `{ "code": "request_conflict", "error": "..." }`.

Все ошибки должны соответствовать существующей Backend-схеме `ErrorResponse`;
технические сообщения внутренних сервисов не возвращаются клиенту.

## Блокирующий риск: cookie path

Сейчас Backend выставляет cookie `demo_chat` с `Path=/api/chat`. Такая cookie
не отправляется браузером на `GET /api/presentations/{id}`, поэтому владельцу
сессии не удастся скачать PDF, даже если доступ к artifact проверяется
правильно. Для сквозного сценария Backend должен выставлять `Path=/api` и
покрыть интеграционным тестом одинаковый session ID на chat и download
endpoint. Не принимать ручную подстановку cookie через DevTools как успешный
результат проверки.

## Команда для smoke test окружения

Из корня репозитория:

```bash
docker compose config -q
docker compose up -d --build
docker compose ps
curl -fsS http://localhost:18080/health
curl -fsS http://localhost:8000/health
```

Для проверки бизнес-сценариев используй UI и браузерную вкладку Network: это
позволяет проверить поведение cookie, статусы ответов и скачивание как у
реального пользователя.
