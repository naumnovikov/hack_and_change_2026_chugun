## 🧠 Архитектура агента (Agentic pattern)
Поток одного запроса:
1. Frontend шлёт сообщение → Backend (Go)
2. Backend достаёт контекст пользователя (кто, какая неделя) из Postgres
3. Backend ищет RAG-контекст в pgvector
4. Backend собирает промпт (system + контекст + RAG + tools) → Ollama
5. LLM решает: ответить текстом ИЛИ вызвать tool (например, `create_access_request`)
6. Если tool — Backend вызывает мок-сервис, возвращает результат в LLM
7. LLM формирует финальный ответ → Backend → Frontend (через SSE)

**LLM не общается с моками напрямую.** Между ней и сервисами стоит Backend.

## 🔧 Инструменты агента (Tools / MCP)
- `create_access_request(service_name, user_id)` → `{ticket_id, status}`
- `send_message(recipient_id, text)` → `{message_id, sent_at}`
- `find_employee(service_name)` → `{name, role, mattermost_id}`

У каждого инструмента будет spec в `specs/tools/*.spec.md` (spec-kit).
