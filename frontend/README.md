# Frontend AI-buddy

Единый адаптивный чат React + TypeScript для трёх MVP-сценариев. Отдельных вкладок для сценариев нет:

- вопрос отправляется в `POST /api/chat`, ответ и HTTP(S)-источники отображаются в общей истории;
- запрос на доступ, уточнение и подтверждение проходят через `POST /api/chat`;
- владелец и черновик приходят от Backend; пользователь пишет «подтверждаю» или «отмена» в чате.

Frontend передаёт все сообщения через единый Go API. При заданном
`AI_INTERNAL_TOKEN` Go использует Python `/agent/step` и исполняет только
проверенные demo tools; без токена остаётся совместимый demo-chat/RAG маршрут.
Заявки и сообщения сохраняются как синтетические demo-записи, корпоративные
сервисы не вызываются. Поиск владельца использует синтетический каталог.
История сообщений хранится в памяти страницы.

## Запуск через Docker Compose

Из корня репозитория:

```bash
docker compose up --build -d
docker compose ps
```

Откройте http://localhost:3000. Frontend собирается в статические файлы и раздаётся Nginx. Запросы `/api/...` Nginx проксирует на Go Backend внутри Compose-сети; браузеру не требуется отдельный CORS-доступ к Backend.

## Локальная разработка

Нужны Node.js 20.19+ в ветке 20 либо 22.12+ и npm. Запустите Backend на локальном порту `8080`, затем из `frontend/`:

```bash
npm ci
npm run dev
```

Откройте http://localhost:5173. Vite проксирует `/api` на `http://localhost:8080`. Для другого локального порта задайте, например:

```bash
BACKEND_PROXY_URL=http://localhost:18080 npm run dev
```

## Проверки и coverage

```bash
npm run lint
npm run build
npm run test:coverage
```

Vitest/React Testing Library проверяют API-клиент, ответы/ошибки UI, повторы безопасного chat-запроса и три сценария. Покрытие строк прикладного кода должно быть не ниже установленного порога `81%`; создаются текстовый, LCOV и Cobertura отчёты в `coverage/`. Frontend CI загружает эту папку как artifact `frontend-coverage`.

## Ограничения интеграции

- AI отвечает по разрешённому RAG-контексту с источниками; для этого нужны доступная модель и подготовленный индекс по `ai-service/README.md`. Без релевантного контекста возвращается честный отказ.
- В agent-режиме AI предлагает tool calls, а Go проверяет и исполняет их по demo allowlist. Это ограниченный демонстрационный agent flow, а не универсальная автоматизация.
- Mock-заявки и сообщения — демонстрационные записи. Реальные доступы не выдаются, сообщения коллегам не отправляются.
- Реальные IAM/авторизация, история диалога на сервере и SSE не реализованы. Демонстрационная cookie/сессия не является удостоверением личности.
- Используйте только synthetic/open data; не вводите реальные персональные или закрытые сведения.

### Контракт серверного демо-чата

Все сообщения, включая команды, подтверждение и отмену, идут в POST /api/chat.
Frontend передаёт X-Request-ID и сохраняет cookie диалога. При ошибке «Повторить
запрос» использует тот же ключ и текст; новая отправка заблокирована до получения
результата, чтобы не менять порядок действий. Mock API напрямую из UI не вызывается.

Проверка в браузере:
1. «Оформи доступ к Jira» → черновик → «отмена» → заявка не создаётся.
2. «Оформи доступ к Jira» → «подтверждаю» → номер DEMO-ACCESS и статус.
3. «Найди владельца billing» → адресат и текст → «подтверждаю» → DEMO-MSG.
4. Вопрос о SPT → RAG-ответ с источником при подготовленной базе и доступной модели; вопрос о ZBP → отказ без выдуманного источника.
