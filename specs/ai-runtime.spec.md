# AI runtime v1: реализованный Python-контракт

Область: AI-инженер. Дополняет agent.spec.md и rag-chunks.spec.md.
Python предлагает инструменты, но не выполняет их и не заменяет IAM Go.
Машиночитаемый контракт: ai-service/openapi.yaml, JSON как подмножество YAML.

## RAG /chat

POST /chat принимает только {message}, 1–8000 символов после trim.
Ответ: {reply, sources: [{title, url}]}. Совместим с предложением Backend
из feat/backend-postgres-chat. Endpoint использует только публичный корпус,
не принимает user_id, историю, права или закрытые материалы из браузера.

Embeddings: Ollama embeddinggemma, 768 измерений. Есть OpenAI-совместимые
/embeddings и /chat/completions через env. В контекст попадает top_k чанков,
удовлетворяющих порогу cosine distance. Для латинских терминов дополнительно
нужно точное совпадение слова в тексте чанка.
Модель выдаёт JSON по схеме GroundedAnswer. Внутренние ссылки C1/C2/C3 и цитаты
проверяются по найденным фрагментам, пробелы нормализуются. URL берёт Python
из metadata, не из генерации. Проверка цитаты не доказывает все утверждения
ответа: смысловое качество отдельно проверяется на контрольных вопросах.
При пустом контексте генерация не запускается, возвращается честный отказ.

## Индексация

python -m ingest читает только sources.json и получает embeddings батчами.
В одной транзакции заменяется коллекция ai_knowledge_chunks, повтор не создаёт
дубли. Ошибка модели не удаляет прежние данные, ошибка SQL откатывает замену.
Импорты сериализованы advisory lock. Коллекция включает версию, provider,
embedding-модель и размерность; векторная колонка не ограничена размерностью.
Смена модели/размерности требует новой индексации. Замена весов под прежним
тегом также требует ingest; автоматической проверки digest нет.
Порог по умолчанию 0.35 — начальная настройка для малого корпуса, не универсальная
оценка качества. Полный перебор подходит шести чанкам; ANN-индекс не добавляется.
Поддерживаются только public/editorial_summary. Неизвестные типы не становятся
публичными автоматически. Закрытый RAG потребует отдельной ACL-схемы и фильтрации.

## Внутренний /agent/step

Для tool calling нужен AI_INTERNAL_TOKEN минимум 32 символа и совпадающий
X-AI-Internal-Token. Это credential Go -> AI, не пользовательская авторизация.
Go использует существующий IAM и не отдаёт credential браузеру. AI размещается
в закрытой сети; на недоверенном канале нужен TLS. При пустом token endpoint отключён.

Запрос: request_id, conversation_id, message, user_context (user_id, role
Intern/Mentor, team_id, onboarding_week), tool_steps (0 по умолчанию),
allowed_services, allowed_recipients, explicit_access_request, confirmed_message,
tool_result. Полные required/типы и ограничения — в OpenAPI.
Все поля, кроме message, формирует доверенный Go. Произвольная история и
контекст продолжения из браузера не принимаются.

Ответ kind=answer: state, reply, sources. kind=tool_call дополнительно содержит
tool_call {call_id,name,arguments}. Это предложение, не выполненное действие.
Разрешены create_access_request(service_name), find_employee(service_name),
send_message(recipient_id,text). Лишние аргументы (включая user_id) запрещены.
За вызов — одно предложение, при tool_steps>=3 новые tools не предлагаются.
Для заявки нужны explicit_access_request от Go и сервис из allowed_services.
Для сообщения нужны allowed_recipients и точное совпадение с confirmed_message.
Пробелы подтверждённого текста не изменяются. До подтверждения send_message
не предлагается модели. Текстовые заявления модели об успехе не выдаются за результат.

call_id детерминирован от user_id/conversation_id/request_id/tool_steps.
Go сохраняет эти значения при повторной доставке; смену аргументов под тем же
ключом отклоняет Go. Новое request_id для повтора операции недопустимо.

Продолжение: Go сверяет call_id с сохранённым предложением и владельцем диалога,
проверяет права, выполняет/восстанавливает операцию с тем же ключом, сохраняет
результат, увеличивает tool_steps и передаёт tool_result {call_id,name,status,result}.
status=success/error/unknown. Python валидирует успешный result и показывает
подтверждённые ID/статус/время без нового вызова LLM. find_employee возвращает
сведения о демо-владельце и запрос текста/подтверждения. При error/unknown нет retry.

Python stateless: владение диалогом, история, TTL и отзыв подтверждения,
проверка call_id, каталог сервисов, IAM, идемпотентность и хранение — задачи Go.
Статусы заявок пока непустые строки: окончательный enum утверждает Backend.
Это зависимости интеграции, а не уже реализованные гарантии Go.

## Ошибки и demo

Ошибки {code,error} не содержат URL БД, ключи, промпты и upstream-диагностику.
422 — ввод, 403 — сервисный credential, 503 — настройка/недоступность,
504 — timeout, 502 — неверный ответ модели, embedding, tool call или result.
Внешние вызовы имеют TIMEOUT_SECONDS (180 по умолчанию), retry отсутствуют.
Синхронные FastAPI handlers работают в thread pool, не блокируя event loop.
Go нужен общий timeout больше embedding + генерация с запасом на cold start.
Проверка keyword-отказа финансовых/чувствительных тем дополняет системный промпт,
но не заменяет серверную проверку прав и назначения операции в Go.

LLM_PROVIDER=demo явно включает hash-embeddings и помеченную выдачу фрагмента
без нейросетевой генерации. Tools не предлагаются. Postgres нужен и в demo.
При сбое production тихий fallback не включается. Смена provider требует ingest.

## Проверки и интеграционные зависимости

Unit-тесты не требуют сети, БД и скачивания модели. Покрытие всех прикладных
Python-модулей строго >80%. TEST_DATABASE_URL включает настоящий pgvector
(service в AI-CI), AI_LIVE_TESTS=1 — отдельный прогон настоящей модели.
Полный E2E требует Backend orchestration, trusted context, подтверждений,
идемпотентности, SSE и Frontend. Они находятся за пределами AI-роли.
