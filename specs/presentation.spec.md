# US3: PDF-черновик презентации по выполненным задачам

Статус: согласованный scope и контракт. Синтетический fixture и Go-фильтрация
завершённых задач реализованы в `backend/jira_tasks.go`; AI-генерация,
PDF-рендеринг, API-вложение и Frontend ещё не подключены. Основание:
согласованный сценарий в `docs/CJM.md`.

## Границы MVP

- Генерация начинается только по явному запросу пользователя через чат.
- Источник — `backend/testdata/jira_issues.json`, синтетический Jira mock.
- В выборку Go включает только задачи с `status=done` и `assignee_id`, равным
  доверенному demo user ID. Нельзя брать user ID из текста или аргументов LLM.
- Результат — скачиваемый PDF из пяти слайдов. Визуальный стиль вдохновлён
  Avito, но документ помечен «Демо-черновик» и не выдаётся за официальный
  материал компании. Не использовать неразрешённые логотипы.
- Реальная Jira, расписание, внешняя отправка и публикация не входят в MVP.

## Поток

1. Frontend отправляет обычный `POST /api/chat` с `X-Request-ID` и cookie
   `demo_chat`.
2. При явном запросе AI возвращает предложение `create_presentation` без списка
   задач и без содержимого файла. Go проверяет явность запроса и независимо
   загружает/фильтрует fixture по доверенному demo user.
3. Если выборка пуста, Go возвращает объяснение без PDF и не вызывает генерацию
   содержания.
4. Go отправляет только отфильтрованные `key`, `summary` и `description` во
   внутренний AI endpoint `POST /presentation/draft` с `X-AI-Internal-Token`.
   AI возвращает строго структурированный JSON из пяти слайдов, не PDF.
5. Каждый фактический bullet должен содержать один или более Jira `source_keys`.
   Go отклоняет неизвестные ключи; AI не может включить задачи вне исходной
   выборки или задать ID/ссылку на файл.
6. Go строит PDF из проверенного JSON и добавляет demo-пометку.
7. Ответ чата содержит `reply` и `attachment` с ID, именем, MIME type,
   download URL и сроком истечения. Frontend показывает кнопку скачивания.
8. `GET /api/presentations/{id}` отдаёт PDF только с исходной cookie-сессией,
   которой принадлежит вложение. Cookie `demo_chat` должна иметь `Path=/api`,
   чтобы браузер отправлял её и на `/api/chat`, и на `/api/presentations/{id}`;
   сохранить `HttpOnly`, `SameSite=Strict` и `Secure` при HTTPS. Срок жизни
   ссылки — 1 час. Неизвестный, истёкший или чужой ID не должен раскрывать файл.
9. Повтор исходного `X-Request-ID` с тем же текстом возвращает сохранённый
   ответ/тот же artifact, не создавая новую версию. Тот же ID с другим текстом
   остаётся конфликтом по существующему контракту чата.

## JSON контентной генерации

Вход AI содержит только уже отфильтрованные завершённые задачи:

```json
{
  "tasks": [
    {
      "key": "DEMO-101",
      "summary": "Добавить валидацию заявки на доступ",
      "description": "Добавлена серверная проверка обязательного названия сервиса."
    }
  ]
}
```

Выход AI содержит ровно пять элементов `slides`. Фактические пункты содержат
`text` и `source_keys`; следующий шаг помечается как предложение и не содержит
сроков или обещаний. Неизвестные даты, метрики, технологии, результаты и
достижения не генерируются.

```json
{
  "slides": [
    {"kind": "title", "title": "Мои результаты", "bullets": []},
    {"kind": "summary", "title": "Краткие итоги", "bullets": [
      {"text": "Реализована валидация заявки на доступ.", "source_keys": ["DEMO-101"]}
    ]},
    {"kind": "tasks", "title": "Выполненные задачи", "bullets": [
      {"text": "DEMO-101 — Добавить валидацию заявки на доступ", "source_keys": ["DEMO-101"]}
    ]},
    {"kind": "learning", "title": "Чему научился", "bullets": [
      {"text": "В описании задач есть опыт серверной валидации.", "source_keys": ["DEMO-101"]}
    ]},
    {"kind": "next_steps", "title": "Возможные следующие шаги", "is_proposal": true, "bullets": []}
  ]
}
```

Go проверяет точное количество и порядок `kind`, лимиты длины текста, известность
`source_keys`, корректный JSON и отсутствие дополнительных полей. Пустые или
недостоверные результаты дают понятную ошибку, PDF не создаётся.

## Контракт Backend ↔ Frontend

Расширение успешного ответа `/api/chat`:

```json
{
  "reply": "Готов демо-черновик презентации по 3 завершённым задачам.",
  "attachment": {
    "id": "opaque-short-lived-id",
    "filename": "demo-intern-001-results.pdf",
    "content_type": "application/pdf",
    "download_url": "/api/presentations/opaque-short-lived-id",
    "expires_at": "2026-11-13T21:00:00Z"
  }
}
```

Обычный chat response по-прежнему содержит только `reply` и optional `sources`.
Схему OpenAPI и строгую Zod-схему Frontend обновить в одном PR с реализацией.
Не передавать PDF как Base64 в JSON. Ссылка same-origin. Сессионная cookie
должна быть доступна обоим API-путям через `Path=/api`, оставаясь HttpOnly;
artifact нельзя скачать из другой demo-сессии.

Ошибки:

- Пустая выборка завершённых задач — `200`, объясняющий `reply`, без `attachment`;
  генерация содержания и рендеринг PDF не вызываются.
- Таймаут AI — `504` с существующей схемой `ErrorResponse` и кодом `ai_timeout`.
- Невалидный JSON, неизвестный `source_key` или несоответствие схеме AI — `502`
  с кодом `ai_invalid_response`; PDF не создаётся и не выдаётся.
- Истёкший, неизвестный или принадлежащий другой сессии ID скачивания — `404`
  без раскрытия существования чужого artifact.
- Повтор `X-Request-ID` с исходным текстом возвращает сохранённый результат;
  тот же ID с другим текстом — `409` с кодом `request_conflict`.

## Fixture и приёмка

В `backend/testdata/jira_issues.json` находятся пять синтетических задач:

- `demo-intern-001` получает DEMO-101, DEMO-102, DEMO-103 со статусом `done`;
- DEMO-104 этого пользователя имеет `in_progress` и исключается;
- DEMO-105 имеет `done`, но назначена `demo-intern-002` и исключается.

Проверки:

- результат фильтра для `demo-intern-001` содержит ровно DEMO-101–103;
- иной пользователь не получает чужие задачи; in-progress задачи не попадают в PDF;
- пустая завершённая выборка даёт ответ без attachment;
- неподтверждённый ключ, невалидный JSON и AI timeout не приводят к выдаче PDF;
- ответ включает пять слайдов, источники фактических пунктов и demo-пометку;
- файл имеет `application/pdf`, валидную сигнатуру PDF, скачивается своей сессией
  до истечения срока и недоступен чужой/истёкшей сессии;
- cookie, выданная на `POST /api/chat`, отправляется браузером и при
  `GET /api/presentations/{id}`; в обоих запросах сохраняется одна demo-сессия;
- retry с прежним request ID не создаёт дубликат и возвращает прежний artifact.
