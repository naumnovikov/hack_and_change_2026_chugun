# Чанки и metadata RAG: формат v1

Область: US2, публичные редакционные пересказы в ai-service/knowledge.
Формат не меняет HTTP-контракт чата. Новые зависимости не нужны.

## Источники и вход

sources.json — явный список индексируемых файлов и их происхождения.
Только перечисленные файлы загружаются, README с тестовыми вопросами исключён.
В v1 поддерживается только source_type=public и content_kind=editorial_summary.
Закрытые материалы и синтетика требуют отдельного расширения схемы и правил
доступа; неизвестный тип отклоняется, а не становится публичным автоматически.

Markdown этого корпуса: один H1 с названием, затем служебная преамбула,
затем разделы H2 с содержательным текстом. Преамбула не индексируется,
происхождение берётся из sources.json. Это парсер согласованного формата,
не универсальный Markdown-парсер: кодовые блоки и вложенные разделы не
используются. Документ без H1/H2 отклоняется. Пустые разделы пропускаются.

## Разбиение

Каждый H2 начинает отдельный чанк. Перед его текстом повторяются название
документа и раздел: термин остаётся в контексте каждого фрагмента.
Максимум — 1200 символов Python str, включая добавленный заголовок; это
не токены и не гарантия размера входа embedding-модели. Лимит настраивается.
Длинный текст делится по последнему пробелу/переносу в доступном диапазоне.
Слово длиннее лимита делится по символам. Пробельные символы на границах
частей удаляются; остальные символы и порядок сохраняются. Перекрытия нет.
Слишком малый лимит вызывает ошибку вместо создания пустого чанка.

## Поля результата

| Поле | Значение |
|---|---|
| schema_version | 1 |
| chunk_id | SHA-256 от metadata источника, ревизии документа, лимита, позиции и текста |
| document_id | Стабильный ID материала из sources.json |
| document_revision | SHA-256 локального Markdown после нормализации CRLF и внешних пробелов |
| text | Название, раздел и содержательный фрагмент для поиска/контекста |
| title, section | Названия документа и раздела |
| position | Номер чанка внутри документа с нуля |
| source_url | Проверяемая ссылка на первоисточник в конкретном commit |
| source_revision | Полный 40-символьный commit SHA первоисточника |
| source_type | public |
| content_kind | editorial_summary, явно отличает пересказ от оригинала |

Повтор обработки одинакового входа даёт одинаковые ID. Изменение документа,
metadata или параметров разбиения меняет ID. При будущей переиндексации
заменять набор чанков document_id целиком, удаляя старые ревизии.
Результат сериализуется через Chunk.model_dump(mode="json").
Ошибки чтения/metadata и повтор document_id не скрываются.

## Приёмка

- Реальный корпус даёт шесть непустых чанков с источниками и заголовками.
- Длинные русскоязычные разделы укладываются в лимит, текст не теряется.
- Метаданные преамбулы и проверочные ответы README не попадают в контекст.
- Пустой раздел не порождает чанк; неправильный формат отклоняется.
- Изменение текста/источника меняет ID; CRLF/LF не меняет результат.
- Тесты не обращаются к сети, Postgres или Ollama.

Embeddings, pgvector, порог релевантности и ответ модели — следующие шаги.
